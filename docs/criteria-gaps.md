# Сверка с критериями оценки: что было не закрыто и как закрыто

Сверка решения с листом `05-Критерии-оценки.xlsx` (около 220 аспектов)
проведена 19.11.2026. Ниже — пункты, которых не хватало после первой
версии, и чем каждый закрыт. Всё проверяется автоматически скриптом
`tools/smoke.ps1`: **106 проверок, ошибок 0** (база 31/31 в `verify.sql`,
сборка, 5/5 модульных тестов, сборка web, сквозной сценарий API за три
роли, экраны desktop через `tools/ui-check`).

## В. Модульные тесты

Ровно пять методов (AAA, setUp/tearDown, фиксированная дата). Добавлены
случаи: null-даты, аварийная заявка без причины, неверный порядок
плановых дат, начало в прошлом, пустой список материалов, нулевое и
отрицательное количество.

## Е. Мобильный клиент бригады (сценарий задания, в критериях не оценивается)

| Требование сценария | Где сделано |
|---------------------|-------------|
| Вход по отпечатку | `AndroidPlatform.AuthenticateBiometricAsync` — системный BiometricPrompt, открывает сохранённый сеанс |
| Список заявок бригады и карточка | `GET /api/mobile/orders`, экраны «Заявки» и карточка заявки |
| Старт и завершение в одно нажатие, отчёт | кнопки «Начать работы» / «Завершить и отправить отчёт» |
| Фото «до» и «после» | таблица `work_order_photos`, `POST /api/work-orders/{id}/photos`, камера Android |
| Справочник и инструкции | `GET /api/mobile/reference`, ТО с инструкциями в паспорте |
| Push-уведомления | опрос `/api/notifications` раз в 20 с + системное уведомление (без Google — закрытая сеть площадки) |
| Геолокация на новых сущностях | `work_orders.latitude/longitude` с CHECK; GPS подставляется в форму сам |
| Сканирование QR/штрихкода | ZXing.Net по снимку камеры; наклейки — `docs/qr-labels.html` |
| Офлайн: кэш, черновики, синхронизация | `LocalStore` + очередь операций в `CrewService`, отправка при появлении сети |
| Интерфейс под одну руку | нижние вкладки, кнопки ≥ 52 точек, действия внизу экрана |
